Finding: "Confirm email" is on in Supabase Auth

Not a code defect — a project setting blocked the rest of the live run

Signing up shopnix.qa.1792392398159@gmail.com worked correctly: a real auth.users row was created and the app showed the right message ("check your email to confirm it, then log in"). That's the app behaving correctly for this setting — but it means the test account can't log in until it clicks a confirmation link, which blocks five downstream checks (login, placing a real order, the admin-denial check, My Orders, cart-clear).

This was flagged as a manual step in the implementation plan, since it can only be changed in the Supabase dashboard, not from client code. Pick one:

  1. Turn it off (Supabase dashboard → Authentication → Providers → Email → "Confirm email"). Matches a demo with no email templates wired up. I can re-run the blocked checks immediately after.
  2. Leave it on and manually confirm the one test account so I can finish this run: update auth.users set email_confirmed_at = now() where email = 'shopnix.qa.1792392398159@gmail.com';
  3. Leave it on, skip re-testing — accept that new signups require email confirmation as intended production behavior.
